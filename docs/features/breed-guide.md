# 기능: 품종 가이드

## 목표
반려동물 품종별 기본 건강 특성(호발 질환, 관리 포인트 등)을 미리 생성해두고, 건강 레포트와 챗봇 답변의 배경 지식으로 재사용한다.

## 생성 트리거 및 캐싱
- 반려동물 등록 시 입력된 **품종을 기준으로 1회만 생성**하여 DB에 캐싱한다.
- 동일 품종의 반려동물이 이후 다시 등록되면 **재호출하지 않고 캐싱된 가이드를 그대로 재사용**한다 (품종당 1회 원칙 — `docs/SPEC.md` 7장 토큰 절약 원칙 10번 참고).

## UI 노출
- **건강 레포트 상단에만 고정 노출**된다 (`docs/features/health-report.md` 구성 참고).
- 챗봇 화면에는 UI로 노출하지 않는다.

## 챗봇 연동
- 챗봇이 답변을 생성할 때, 캐싱된 품종 가이드를 시스템 프롬프트 컨텍스트에 **사용자에게 보이지 않게 조용히** 포함해 답변 품질만 높이는 용도로 쓴다 (`docs/SPEC.md` 6.5 참고).
- 이 컨텍스트 주입은 신규 LLM 호출을 유발하지 않는다 — 이미 캐싱된 텍스트를 프롬프트에 덧붙이는 것뿐이다.

## 저장 형태 vs 노출 형태
- **저장(캐싱) 형태**: `docs/API_SPEC.md` §3.3의 3필드 구조를 채택한다 — `trainingTip`(훈련 팁), `chronicDiseases`(품종별 유의 만성질환 — 병명 포함 가능, 개별 반려동물의 자동 저장 기록이 아니라 품종 일반 정보이므로 "대시보드 자동 저장 병명 금지" 규칙과 무관), `specialCare`(1년 미만/10년 이상일 때만 제공, 그 외 `null`). 단일 텍스트 블롭보다 구조화되어 있어 이쪽을 채택.
- **주입/노출 형태**: 챗봇 프롬프트 주입 시점과 레포트 상단 표시 시점에는 위 3필드를 읽어서 텍스트로 합쳐 사용한다 (예: `{trainingTip}\n{chronicDiseases}\n{specialCare가 있으면 추가}`). LLM 재호출 없는 단순 포맷팅이며, 이미 검증된 `CONSULT_SYSTEM_PROMPT`/`REPORT_SYSTEM_PROMPT`는 여전히 "품종 가이드 텍스트 블록" 하나만 받으므로 프롬프트 쪽은 변경되지 않는다.

## guideDocumentUrl (PDF) — 보너스, 핵심기능 아님
`docs/API_SPEC.md`의 Pet 스키마에 있는 `guideDocumentUrl`은 위 텍스트를 실제로 PDF로 렌더링해 호스팅한 뒤 그 경로를 반환하는 용도로만 쓴다 — AI가 URL을 지어내는 일은 절대 없어야 한다. 텍스트 노출(챗봇 컨텍스트/레포트 상단)만으로 핵심 기능은 충분하므로, PDF 생성은 필요 시 나중에 추가하는 낮은 우선순위 항목이다.

## API
- `POST /api/v1/pets/{petId}/ai-breed` — "AI와 함께 세부 종 정보 입력하기" (`docs/API_SPEC.md` §3.3과 동일, 신규 엔드포인트라 기존 문서와 충돌 없음)
  ```json
  // Request
  { "rawBreedInput": "string (예: '미디엄 푸들')" }
  // Response
  {
    "breed": "string (정규화된 품종명)",
    "feedback": {
      "trainingTip": "string",
      "chronicDiseases": "string",
      "specialCare": "string | null"
    }
  }
  ```
  동일한 정규화 결과(`breed`)는 캐싱해서 재사용한다 (품종당 1회 원칙).

## 주의사항
- 품종 가이드 생성 자체도 LLM 호출이 필요할 수 있으므로, 반드시 품종당 1회로 제한해 토큰 소모를 최소화한다.
- 건강 레포트가 재생성될 때도 품종 가이드는 캐싱된 것을 그대로 가져다 쓰고 다시 생성하지 않는다.
