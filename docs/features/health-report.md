# 기능: 건강 리포트 (월간 종합 분석)

## 목표
챗봇 상담 및 대시보드 기록을 기반으로 월간 리포트를 생성한다.

## 기간 기준
- **1달(기본) + 1주(옵션 토글)** 두 단위만 지원한다.
- 하루 단위는 제외한다 — 하루 단위는 AI 종합소견을 내기엔 데이터가 부족하고, 기존 대시보드 로그가 이미 그 역할을 커버한다.

## 참고 데이터
- 구조화된 약/예방접종 데이터 + 수동 입력된 과거 증상 데이터를 참고한다.
- 이 참고 데이터는 대시보드의 표시 range(1개월)와 무관하게 **전체 기간**을 조회한다.

## 구성 (상단 → 하단 순서)
1. **품종 가이드 (상단 고정)** — `docs/features/breed-guide.md` 참고
2. **종합소견** — 체중추이 + 복용약 + 증상 타임라인 기반
3. **앞으로의 케어가이드**

## 소견 작성 스타일 (순서 고정)
1. 시기별 타임라인 정리
2. 종합 판단
3. 실천 가이드

## 트리거
- **자동 생성**: 주 1회
- **수동 새로고침**: 사용자가 버튼으로 직접 재생성 요청 가능
- 주간 옵션은 `GET /pets/{petId}/report/monthly`에 `period=week|month`(기본값 `month`) 쿼리 파라미터로 구현 완료. 이 옵션은 "체중 변화"/"증상 타임라인" 표시 range에만 영향을 준다 — 종합소견/케어가이드/diagnosisOpinions는 원래 설계대로 항상 전체 기간 컨텍스트로 생성되고 캐싱도 `period`와 무관하게 (petId, year, month) 기준 그대로 유지된다 (LLM 재호출 최소화 원칙 유지).

## 캐싱
- 동일 기간 내 참고 데이터(체중/복약/예방접종/증상)에 변화가 없으면 재생성을 스킵하고, 캐싱된 레포트를 그대로 재사용한다.

## diagnosisOpinions 매핑
소견은 내부적으로 위 "소견 작성 스타일"(3단계 내러티브, `scripts/prompt-test/prompts.py`의 `REPORT_SYSTEM_PROMPT`로 검증 완료)로 생성한다. `docs/API_SPEC.md` §2.4의 `diagnosisOpinions[{id,text}]`(평탄화된 리스트)로 응답할 때는, 이 내러티브의 "종합 판단"+"실천 가이드"에서 개별 실행 항목을 뽑아 항목별로 쪼개 반환한다 — 프롬프트를 다시 설계하는 게 아니라 생성된 텍스트를 후처리로 나누는 것.

## 출처 표기
`diagnosisOpinions[].text`의 `[출처]`도 `docs/SPEC.md` 6.4의 고정 카테고리 라벨 3종(일반 수의학 상식 / 품종별 유전질환 정보 / 등록된 데이터 기반 추정)만 사용한다.

## 품종 평균 체중 비교 (구현됨 — breed-guide.md standardWeightKg 참고)
`docs/API_SPEC.md`의 `weightChange.analysisMessage` 예시("평균 푸들보다 0.9kg 높아요")는 품종 평균 체중 데이터를 전제로 하는데, 현재 `breed-guide.md`를 포함해 이 데이터의 출처가 정해져 있지 않다. 데이터 소스가 확보되기 전까지는 미구현 상태로 남겨둔다 (낮은 우선순위).

## API
- `GET /api/v1/pets/{petId}/report/monthly?year=YYYY&month=MM` — 경로는 기존 pet-scoped 구조 유지, 쿼리파라미터는 `docs/API_SPEC.md` 스타일(`year`+`month` 분리)로 맞춤
- 응답에 `hospitalQuestions` 필드 포함. `docs/API_SPEC.md` 원본 예시는 필드명("질문")과 값(진술문)이 불일치해 명세 오류로 보고, 질문형 수정안을 제안함: `"체중 감소와 무관하게 증상이 지속되면 관절염이나 통풍 검사를 받아야 하나요?"` — 실제 의도는 김학래 확인 필요.

## 주의사항
- "AI가 분석한 정보는 정확하지 않을 수 있습니다" 같은 면책 문구를 리포트 하단에 항상 노출
- 리포트 생성 자체에 LLM을 추가 호출할지, 챗봇 대화에서 이미 만든 `suspectedSymptom`을 재사용할지는 토큰 예산상 **재사용을 우선**한다 (신규 호출 최소화)

## 구현 반영 — 지난달 조회 / 복용률
- `year`/`month`로 지난달 레포트를 조회할 수 있다 (미래 달은 400). 컨텍스트는 해당 월 말일까지의 데이터만 넣으므로, 지난달 레포트는 이후 기록이 쌓여도 캐시가 깨지지 않는다. 이번 달 컨텍스트는 기존과 동일해 기존 캐시가 유지된다.
- 응답에 `medicationAdherence[]{title, taken, expected, rate}` / `overallAdherenceRate`를 추가했다. 기간(월/주) 내 doseLog 집계로 계산하며 LLM을 쓰지 않는다.
- 화면: 제목 양옆 화살표로 월 이동 (반려동물 등록 월 ~ 이번 달). 주간 토글은 이번 달에만 노출. "인쇄·PDF" 버튼은 브라우저 인쇄를 쓰며 NAV/알림 토스트는 인쇄 시 숨긴다.
- 서버도 등록 이전 달 요청은 400으로 막는다 (등록일 = 펫 ObjectId 생성 시각, `PetOut.createdAt`).
